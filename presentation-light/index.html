Architecture & Security

  • Firebase Realtime Engine: Outing sessions aren't static—they change live. Firebase handles this sub-100ms syncing instantly, letting us bypass custom socket infrastructure.
  • Strategic Data Duplication: Unlike SQL, we intentionally duplicate NoSQL data (like user avatars). This completely eliminates slow server-side JOINs, loading entire UI views in one request.
  • Optimize for Reads (1:1000): Sessions are written once but polled thousands of times. By flattening the schema, we guarantee O(1) fetch times. Storage is cheap; query speed is everything.
1. Why Firebase? We're dealing with something that's constantly changing. An outing session isn't static—people are joining, locations are updating, decisions are happening live. Firebase gave us that out of the box with very low latency. 2. NoSQL Denormalization: We store user data like avatars directly inside the outing session. This removes the need for joins. The app loads everything it needs in one single request. 3. Prioritizing Reads over Writes: Creating a session happens once. But after that, it's being read constantly. We guarantee O(1) document fetch times.

Security & Performance Metrics

  • Absolute Privacy (12h TTL): All session data is auto-destroyed after 12 hours. Upon arrival at the venue, live-tracking ceases immediately. Zero historical GPS data is retained.
  • Role-Based Host Security: Security rules restrict Guests from modifying routing states. Only the authorized Host can alter the calculation matrix, preventing spoofing.
  • Matrix Routing (< 3.0s): The Google API evaluates 8 participants against 10 venues (80 coordinate elements) and resolves the midpoint in under 3 seconds.
  • WebSocket Polling (~25ms): Coordinate updates are broadcast across all active clients with 25ms precision, ensuring continuous real-time synchronization.
Security wasn't an afterthought for Laween. We wrote backend rules enforcing a strict 12-hour TTL. The database automatically wipes the session. The nanosecond you arrive, your GPS stream is permanently severed. We also implemented "Dictator" security rules—only the Host can trigger calculations. On performance: 80 matrix calculations resolved in under 3.0 seconds. WebSockets at 25ms.
