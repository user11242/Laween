Why Firebase?

Outing sessions are live and constantly changing. We needed real-time, not request-response.

Real-Time Sync

WebSocket-based, sub-100ms data propagation. No polling, no REST overhead.

NoSQL by Choice

Intentional denormalization. We duplicate data to eliminate JOINs. One read loads everything.

Read-Optimized

Sessions are written once, read 1000× more. Flat schema = O(1) document fetch, every time.

Not Just Painted.

We applied the same engineering rigor to the visual language and user experience. The phone UI doesn't just look pretty—it fundamentally works better.

01.

Visual Language

Mint grids, dark teal (`#00697b`), and bubbly shapes built to reduce outing stress.

Color Psychology

Organizing groups is tense. Deep teal establishes calm trust; mint highlights action.

Soft Geometries

Continuous, massive border-radii everywhere. Hard edges create tension; soft edges are approachable.

02.

Dynamic Typography

One app. Two fundamentally different typographic foundations.

English: Nunito

A well-balanced, rounded sans-serif that perfectly mirrors the bubbly UI shapes.

عربي: Cairo

A modern Arabic typeface ensuring native legibility without compromising the brand aesthetic.

03.

Micro-interactions

We replaced jarring real-time validation errors with fluid, intelligent physical feedback.

No "Red Text" Shaming

Users hate seeing red warning text while actively typing. We stripped it out.

Kinetic Haptics

Invalid fields subtly "shake" to indicate an error, mimicking physical resistance. It only triggers upon submission.
